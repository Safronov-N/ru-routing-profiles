# Independent RU Routing

Автообновляемая маршрутизация для Stash на iOS, Shadowrocket и Happ. Профиль использует собственную политику и три независимых входа: [v2fly domain-list-community](https://github.com/v2fly/domain-list-community) для категорий сервисов, [Re-filter](https://github.com/1andrevich/Re-filter-lists) для дополнительных доменов, требующих прокси в России, и [Loyalsoldier GeoIP](https://github.com/Loyalsoldier/geoip) для российских IP-диапазонов. RoscomVPN не участвует в сборке. Опубликованные файлы используют адреса репозитория `Safronov-N/ru-routing-profiles`.

Генератор не содержит VPN-серверов, ключей и учётных данных. `PROXY` использует выбранное в приложении подключение.

Форк RoscomVPN не решает задачу актуальности сам по себе: он сохраняет старую цепочку входных данных и потребует поддерживать её вручную. Здесь источники, правила приоритета, проверки и сборка принадлежат этому репозиторию. v2fly задаёт категории сервисов, Re-filter даёт кандидатов на проксирование, Loyalsoldier обновляет российские IP. Полный сырой Antifilter не подключён: он значительно шире нужного набора и не является проверкой доступности у конкретного провайдера.

## Stash на iOS

Используйте действующую подписку с вашими серверами и включите дополнение **Independent RU Routing**:

1. В разделе **Overrides / Переопределения** добавьте удалённое дополнение по URL:

   ```text
   https://raw.githubusercontent.com/Safronov-N/ru-routing-profiles/main/stash/routing.stoverride
   ```

2. Включите дополнение, расположите его последним среди дополнений, меняющих маршрутизацию, и выберите рабочий VPN-сервер в группе **RU-PROXY**. В подписке должен быть хотя бы один сервер: Stash считает пустую группу прямым подключением.
3. Переподключитесь. Проверьте в журнале соединений: `2ip.ru`, YouTube и ChatGPT → `RU-PROXY`; `gosuslugi.ru`, `nalog.ru`, Ozon → `DIRECT`. Проверка IP должна показывать адрес выбранного VPN-сервера.

Прежняя ссылка `rules/Independent-RU-Routing.stoverride` также обновляется и содержит то же дополнение. Если оно уже установлено, обновите его кнопкой ↻, затем выберите сервер в новой группе **RU-PROXY**; повторно добавлять дополнение не нужно. Для нового подключения достаточно одной ссылки выше.

Дополнение сохраняет серверы подписки и её DNS, включает режим `rule` и заменяет список маршрутов целиком (`rules: #!replace`). Другие дополнения, применённые позднее, могут снова изменить правила. Изменение структуры профиля требует обновления самого override; удалённые списки проверяются с интервалом 21600 секунд, фактическое обновление зависит от работы Stash и iOS.

Семь наборов используют `behavior: domain` и `behavior: ipcidr`, которые Stash оптимизирует по памяти и поиску. Точные домены остаются точными; суффиксы передаются как `+.example.com`. Единственное специальное wildcard-правило остаётся в своей доменной фазе. Национальные зоны, исключения и конечный `MATCH,RU-PROXY` сохраняют общую политику. Private IPv4 и IPv6 проверяются раньше доменов с `no-resolve`; общий российский IP-набор — после доменных правил, с разрешённым DNS-поиском.

DNS намеренно не заменяется неизвестными настройками: дополнение не знает DNS вашего провайдера и частных зон. Для Stash не нужны переносимые из Clash поля `enhanced-mode` или `fake-ip-range`: приложение само использует Fake IP. Если в исходной подписке есть недоступные DNS или неподходящий `fallback-filter`, их нужно исправлять в этой подписке отдельно. Диагностика DNS и журнал соединений Stash позволяют отличить ошибку разрешения имени от выбора маршрута.

Основание: документация Stash [Overrides](https://stash.wiki/en/configuration/override), [Rule Sets](https://stash.wiki/en/rules/rule-set), [Strategy Groups](https://stash.wiki/en/proxy-protocols/proxy-groups) и [DNS](https://stash.wiki/en/features/dns-server).

## Shadowrocket

Импортируйте конфигурацию:

```text
https://raw.githubusercontent.com/Safronov-N/ru-routing-profiles/main/shadowrocket.conf
```

Выберите своё VPN-подключение и режим маршрутизации **Config**. Включите фоновое обновление конфигурации в Shadowrocket и Background App Refresh в iOS. Фактическое время применения новых правил зависит от обновления конфигурации и списков самим приложением.

## Happ

[`happ/happ-routing.json`](happ/happ-routing.json) и [`happ/happ-routing-link.txt`](happ/happ-routing-link.txt) содержат профиль Happ. Генератор создаёт `happ/geosite.dat` с категориями `ROUTING-PROXY` и `ROUTING-DIRECT`, а также `happ/geoip.dat` с категориями `RU` и `PRIVATE`.

Для отдельного импорта используйте ссылку из `happ/happ-routing-link.txt`. Чтобы обновить такой профиль, повторно импортируйте актуальную ссылку и переподключитесь.

Для передачи динамического профиля вместе с подпиской в **3x-ui 3.11.0**:

1. В **Настройки панели → Подписка → Happ → Правила маршрутизации** укажите URL:

   ```text
   https://raw.githubusercontent.com/Safronov-N/ru-routing-profiles/main/happ/happ-routing.json
   ```

2. Сохраните настройки и перезапустите панель.
3. В Happ обновите соответствующую подписку, затем переподключитесь для применения профиля.

При таком подключении новую версию профиля получают обновлением подписки. Happ использует увеличение `LastUpdated` для обновления профиля и повторной загрузки геофайлов. Сам выпуск файлов каждые шесть часов не подтверждает, что клиент их уже применил. Для JSON-подписки Happ профиль должен предоставляться подпиской. Фрагментация настраивается отдельно от маршрутизации.

Для полной Xray JSON-конфигурации Happ передаёт JSON ядру без наложения обычных правил приложения. Профиль управляет геофайлами и Tunnel DNS; маршрутизацию в таком режиме нужно проверять в самом JSON подписки. Это отличается от обычного списка серверов `vless://`. Подробнее — [документация Happ](https://www.happ.su/main/ru/dev-docs/examples-of-links-and-parameters).

## Политика маршрутизации

Доменное правило имеет приоритет перед IP-правилом. Если доменное имя не совпало ни с одним правилом, клиент проверяет IP; конечный маршрут — `PROXY`. Happ использует `DomainStrategy=IPIfNonMatch` и `RouteOrder=block-proxy-direct`.

### Домены

1. Выбранные категории v2fly `youtube`, `telegram`, `github`, `instagram`, `discord`, `google-play`, `openai` → `PROXY`.
2. Ручной [`DIRECT_PRIORITY_DOMAIN.list`](rules/DIRECT_PRIORITY_DOMAIN.list) для ограниченного набора российских государственных, платёжных и торговых сервисов → `DIRECT`.
3. Небольшой список сообщества `community.lst` Re-filter → `PROXY`.
4. Национальные зоны `.ru`, `.рф`, `.su`, `.by` → `DIRECT`.
5. Расширенный `domains_all.lst` Re-filter для остальных зон → `PROXY`.
6. Категория v2fly `category-ru` → `DIRECT`.
7. Независимые категории v2fly для Steam, Apple, Microsoft, Epic Games, Riot, Escape from Tarkov, Twitch, Pinterest и Faceit → `DIRECT`.
8. Всё остальное проверяется по IP, затем попадает в `FINAL,PROXY`.

Сервисы проверки внешнего адреса, перечисленные в конфигурации, принудительно идут через `PROXY`. Широкий список Re-filter содержит десятки тысяч национальных доменов, в том числе возможные ложные срабатывания; поэтому он не переопределяет национальный `DIRECT`. Явные категории сервисов и список сообщества имеют более высокий приоритет. Для Happ национальные записи широкого списка исключаются из `ROUTING-PROXY`, чтобы порядок совпадал с Shadowrocket. Ручной приоритетный список размещён перед Re-filter для сервисов, которым нужен российский адрес; его расширение требует проверки на устройстве.

Зарубежные исключения размещены после Re-filter. Поэтому Steam идёт напрямую, а отдельно перечисленные заблокированные адреса Microsoft и Twitch остаются через прокси. Две регулярки v2fly преобразуются отдельно: OpenAI — в `DOMAIN-WILDCARD,chatgpt-async-webps-prod-*-*.webpubsub.azure.com` (для Happ — эквивалентное регулярное выражение с якорями); Epic Games — в десять точных имён `epicgames-download0.akamaized.net` … `epicgames-download9.akamaized.net`. Wildcard OpenAI сохраняет префикс и зону сервиса, но не воспроизводит ограничения исходной регулярки на символы и цифры полностью. Широкие `DOMAIN-KEYWORD` для этих сервисов не используются. Отрицательные проверки защищают от совпадения посторонних доменов и подмены суффикса. Пропуски исходных регулярных выражений записаны в манифесте.

Административные зоны из секции ICANN официального [Public Suffix List](https://publicsuffix.org/list/) исключаются из обоих списков Re-filter. Это защищает от правил вроде `com.cy` и `gov.pl`, которые охватывают множество независимых сайтов. Исключается сама административная зона, а конкретные записи вроде `politis.com.cy` сохраняются; `2gis.com.cy` получает свой DIRECT из v2fly. Частная секция PSL не участвует: правила сервисов и платформ, например `pages.dev`, `notion.site`, `gitlab.io`, сохраняются. Учитываются IDN, wildcard-зоны и исключения PSL.

### IP

Локальные и private диапазоны идут напрямую; ранние правила с `no-resolve` не вызывают преждевременный DNS-запрос. Для остального трафика `DIRECT_IP.list` строится из `Loyalsoldier/geoip` `ru.txt`, затем `GEOIP,RU` Shadowrocket служит дополнительным fallback. Остальные IP идут через `FINAL,PROXY`.

Широкие IP-списки Re-filter, включая DNS-производные сети и общие CDN-диапазоны, не подключаются. Они могут направить через прокси посторонний сервис. В Happ категория `PRIVATE` собирается из фиксированных private диапазонов, а `RU` — из того же проверенного `ru.txt`.

## Автоматическое обновление

[`update-rules.yml`](.github/workflows/update-rules.yml) запускает генерацию каждые шесть часов и при изменениях кода. Генератор:

1. Фиксирует SHA входных GitHub-репозиториев и загружает каждый набор из одного снимка.
2. Проверяет формат доменов и CIDR, ожидаемые категории, объём и сохранность состава правил относительно предыдущей публикации.
3. Пропускает записи v2fly с атрибутами `@...` при построении общих категорий. Это намеренно исключает в том числе рекламные, телеметрические и китайские подмножества; категории переносятся не полностью. Для пропущенного домена остаются другие совпадающие правила и последующая IP-фаза.
4. В каждом сгенерированном доменном списке и каждой категории Happ удаляет только записи, полностью покрытые оставшимся `DOMAIN-SUFFIX` в том же наборе. Типы правил, порядок оставшихся записей и приоритеты списков сохраняются; точное имя не превращается в suffix, `DOMAIN-KEYWORD` не сокращается. IP-списки не минимизируются.
5. Создаёт собственные ruleset-файлы, профиль Happ и geo-файлы; записывает происхождение и исходные объёмы до минимизации в `rules/SOURCE_MANIFEST.txt`. Затем автономный `generate-stash.main.kts` создаёт дополнение Stash и семь списков из тех же правил. Несжатые доменные входы сохраняются в `build/domain-rules/` для проверки этой сборки.
6. Проверяет равенство доменного покрытия до и после минимизации, включая готовый Happ `geosite.dat`, порядок правил и контрольные маршруты, после чего публикует весь результат.

Если источник недоступен или проверка не прошла, выпуск не публикуется; последняя опубликованная версия остаётся доступной. Отдельно сообщается возраст входных списков. Неизменная дата коммита сама по себе не доказывает, что данные неверны, поэтому только по возрасту сборка не останавливается.

Расписание GitHub Actions работает по принципу best effort: [GitHub допускает задержку или пропуск запуска и отключает расписание публичного репозитория после 60 дней без активности](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows). Поэтому состояние последнего успешного запуска нужно отслеживать отдельно; `workflow_dispatch` позволяет запустить обновление вручную.

Re-filter поставляет кандидатов на проксирование, но его списки и измерения не являются доказательством доступности каждого домена у конкретного провайдера. Контрольные маршруты защищают от известных ошибок конфигурации; проверка приложений на устройстве и сети пользователя остаётся необходимой.

## DNS и локальные сети

Shadowrocket использует `tls://common.dot.dns.yandex.net`, fallback `https://dns.google/dns-query#proxy`, `https://cloudflare-dns.com/dns-query#proxy` и `system`. `dns-direct-fallback-proxy = false` не переводит DIRECT DNS на proxy fallback; `private-ip-answer = true` допускает private DNS-ответы для локальных сетей. Массовый `always-real-ip` из прежнего профиля не используется.

Happ сохраняет DNS-серверы и DoH-поля ранее проверенного пользователем профиля: удалённый `8.8.8.8`, прямой `77.88.8.8`. В профиле Happ по умолчанию включён FakeDNS (`FakeDNS=true`). Прежние фиксированные адреса `nalog.ru` в `DnsHosts` удалены: 27 октября 2026 года прямой DNS возвращал для `lkfl2.nalog.ru` два IP, а старая запись закрепляла только один. Сходство маршрутов Shadowrocket и Happ не означает идентичность их DNS-поведения. Конфиг не настраивает split-DNS для частных зон другой VPN.

## Проверка и разработка

```bash
kotlinc -script scripts/generate.main.kts
kotlinc -script scripts/generate-stash.main.kts
kotlinc -script scripts/verify-routing.main.kts
```

Автоматически создаются `rules/PROXY_DOMAIN.list`, `rules/PROXY_REFILTER_COMMUNITY.list`, `rules/PROXY_REFILTER_DOMAIN.list`, `rules/DIRECT_DOMAIN.list`, `rules/DIRECT_FOREIGN_DOMAIN.list`, `rules/DIRECT_IP.list`, `rules/SOURCE_MANIFEST.txt`, `shadowrocket.conf`, `happ/*` и `stash/*`. `rules/DIRECT_PRIORITY_DOMAIN.list` поддерживается вручную. Временные проверочные входы `build/*` не публикуются.

Pull request повторно запускает генерацию и проверяет созданные маршруты всех трёх клиентов. Чистый diff после загрузки latest не требуется: новые входные списки могут появиться независимо от изменений PR. Основная ветка публикует результаты только после всех проверок. В рабочем профиле видимый результат зависит также от выбранного сервера, DNS, доступности источников правил и сети провайдера.

### Защитный снимок Public Suffix List

[`data/public_suffix_list.dat`](data/public_suffix_list.dat) — локальный снимок официального PSL. При генерации он не скачивается; версия и SHA-256 записываются в `rules/SOURCE_MANIFEST.txt`. Повреждённый файл останавливает сборку до записи результатов. Секция ICANN служит только защитой от слишком широких записей Re-filter и не выбирает маршрут конкретного сервиса.

Снимок обновляется отдельно из `https://publicsuffix.org/list/public_suffix_list.dat`, с сохранением заголовков и лицензии, после чего запускаются обе команды проверки выше. Официальный источник просит загружать PSL не чаще одного раза в сутки. Изменение снимка или Kotlin-скриптов запускает обычную проверку и генерацию CI.
